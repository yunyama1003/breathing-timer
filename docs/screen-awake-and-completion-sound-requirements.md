# 画面スリープ対策・終了音の要件

対象: PWA版（`site/`）とSpring Boot版の呼吸タイマー画面。既存の呼吸設定、保存、バックアップ、時間計算は変更しない。

## 現状

- 両版ともページが非表示になるとタイマーを一時停止する。画面がスリープした場合も継続できない。
- PWA版は呼吸フェーズの切り替え時にWeb Audioで短い音を鳴らす。Spring Boot版は`change.mp3`を再生する。タイマー完了時の専用音はない。
- 音のオン／オフは両版にある。

## 1. 実行中の画面スリープ対策

1. ユーザーが「スタート」または「再開」を押し、タイマーが実行中になったときに、対応ブラウザではScreen Wake Lock APIで画面の点灯維持を要求する。
2. 一時停止、リセット、完了、ページ離脱ではWake Lockを解放する。準備中・一時停止中・完了後は点灯維持を要求しない。
3. ブラウザや端末がWake Lockを許可しない場合も、タイマーの開始・進行・操作は妨げない。利用できないことを簡潔に知らせる。
4. Wake Lockが端末都合で解除されても、実行中かつページが表示中の場合だけ再取得を試みる。無制限に再試行しない。
5. ページが非表示になった場合は、現在の「自動で一時停止し、手動で再開する」動作を維持する。画面ロック中や他アプリ表示中のバックグラウンド実行は保証しない。

## 2. 専用の終了音

1. 最後の呼吸サイクルが終わり、タイマーが`completed`へ遷移したとき、通常のフェーズ切り替え音と聞き分けられる短い終了音を一度だけ鳴らす。候補は音程が上がる2音程度の穏やかな通知音とする。
2. フェーズ切り替え音は従来どおり残す。完了時にはフェーズ切り替え音を重ねず、終了音だけを鳴らす。
3. 音がオフなら、通常音も終了音も鳴らさない。音声再生の失敗や非対応端末でも、完了表示とタイマーの状態を妨げない。
4. 一時停止・リセット・設定変更では終了音を鳴らさない。完了後に「もう一度」で再実行した場合は、その実行が完了したときに再び一度だけ鳴らす。

## 受け入れ条件・テスト

- PWA版とSpring Boot版で、開始・再開時にWake Lockを要求し、一時停止・リセット・完了・ページ離脱時に解放することを確認する。
- Wake Lock非対応・拒否・途中解除でもタイマーが操作でき、非表示時の一時停止が維持されることを確認する。
- 模擬時計で通常のフェーズ切り替え、最後までの完了、遅延更新で完了時刻を飛び越えた場合、停止・リセット、再実行、消音を検証する。終了音は1回の完了につき1回だけとする。
- スマートフォンの実機で、画面を表示したまま「リラックス 5分」を最後まで実行し、点灯維持と終了音を確認する。iPhoneとAndroidの利用対象ブラウザで確認し、非対応や省電力設定による制限は記録する。
- PWAの変更時はService Workerのキャッシュ版を更新し、公開版で新しいコードが配信されることを確認する。

Screen Wake Lock APIはHTTPSまたはlocalhostなどの安全なコンテキストで利用できるが、ブラウザ・端末・省電力状態によって拒否または解除され得る。そのため、画面の点灯を常に保証する機能としては扱わない。

参考: [W3C Screen Wake Lock仕様](https://www.w3.org/TR/screen-wake-lock/)、[MDN Screen Wake Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)
