# 呼吸タイマー 改善要件定義書

作成日: 2026-09-08  
対象: breathing-timer / ローカルコミット `51365dcfc63ddfe7869bb4efb821860308686781`  
状態: 実装前の仕様案。GitHub上の最新版との差分は未確認。

## 1. 目的・範囲

入力ミスで処理が中断する問題とタイマーの時間・表示の不整合を修正し、初めて取得した開発者が再現可能な手順で起動できる状態にする。

今回の必須範囲は R-01〜R-06 とする。R-07〜R-09 は追加改善、R-10 は外部公開前の必須条件とする。アカウント機能、実施履歴の新設、デザイン全体の刷新は今回の必須範囲に含めない。

## 2. 前提・現状

- Java 25、Spring Boot 4.0.1、Thymeleaf、PostgreSQL、Gradle Wrapperを使用している。
- 現在保存しているのはタイマー開始前の設定値であり、完了したトレーニングの実績ではない。
- 入力制約はEntityに存在するが、Controllerで入力エラーをフォームへ返す処理がない。
- JavaScriptの模擬実行では、吸う1秒・止める0秒・吐く1秒が3秒になり、完了後の開始ボタンが「再開」のままになることを確認済み。
- JavaのテストはGradleキャッシュディレクトリの作成エラーにより未実行。バックエンドと実ブラウザの動作は実装時に検証する。

## 3. 機能要件

### R-01 入力検証とエラー表示【必須・優先度高】

入力用DTOを作り、次の制約をサーバー側で検証する。Entityの永続化時の制約も維持する。

| 項目 | 必須 | 許容値 |
| --- | --- | --- |
| 吸う秒数 | 必須 | 整数1〜30 |
| 止める秒数 | 必須 | 整数0〜30 |
| 吐く秒数 | 必須 | 整数1〜30 |
| 回数 | 必須 | 整数1〜20 |

- 未入力、範囲外、小数、文字列、Integerの範囲を超える値は登録しない。
- エラー時は登録フォームを再表示し、送信された値と項目別の日本語エラーを表示する。数値変換エラーも処理する。
- HTMLにも `required`、`min`、`max`、`step="1"` を設定する。サーバー検証を必須とする。
- 入力欄のラベルを `for` と `id` で関連付け、エラーを `aria-describedby` で参照できるようにする。
- `id`、`createdAt` は入力DTOに含めず、サーバーで管理する。Entity全体を入力検証すると保存前の `createdAt` が未設定のため、DTOで責務を分ける。

完了条件: 正常値は1件保存されてそのIDのタイマーへ遷移する。不正値はDBに保存されず、500エラーにならずにフォーム上で修正できる。

### R-02 0秒フェーズの処理【必須・優先度高】

- 止める秒数が0の場合、そのフェーズを表示・待機せず、吸うから吐くへ直接遷移する。
- 遷移音は実際に表示する次フェーズへの切り替えで1回だけ鳴らす。0秒フェーズによる重複再生をしない。
- 設定上の総時間は `(吸う秒数 + 止める秒数 + 吐く秒数) × 回数` とする。

完了条件: 模擬時計で「1・0・1秒、1回」が2秒で完了し、途中に0秒や負数のカウントを表示しない。

### R-03 経過時間に基づくタイマー【必須・優先度高】

- `setInterval` の呼び出し回数ではなく、単調増加時計（`performance.now()`等）の差で経過時間を求める。
- 内部の時間はミリ秒で保持する。表示秒数は残りミリ秒を切り上げ、負数を表示しない。
- 遅延後の更新では超過時間を次フェーズへ引き継ぎ、必要なら複数フェーズを進めて正しい位置に追いつく。経過した全フェーズの音を連続再生しない。
- 一時停止で残りミリ秒と円の進捗を保持し、再開後はその位置から進める。停止中の時間は計測しない。
- 円の拡大・縮小、フェーズ名、カウント、サイクル数を共通の時間・状態から更新する。
- タブが非表示になった場合は自動で一時停止し、戻ったときは「一時停止中」と表示する。再開はユーザー操作で行う。
- ブラウザやOSによる実行停止中の音声通知は保証対象外とする。

完了条件: 模擬時計で遅延更新と1秒未満での停止・再開を検証し、経過時間の消失や積み重なる延長がない。前面の実ブラウザで表示・円の動きが一致する。

### R-04 操作状態とボタン表示【必須・優先度中】

| 状態 | 主ボタン | 一時停止ボタン | 表示 |
| --- | --- | --- | --- |
| 準備 | スタート・有効 | 無効 | 準備、サイクル0 |
| 実行中 | 実行中・無効 | 有効 | フェーズ、残り秒、現在回数/総回数 |
| 一時停止 | 再開・有効 | 無効 | 一時停止中、残り秒、現在回数/総回数 |
| 完了 | もう一度・有効 | 無効 | 完了、最終回数/総回数 |

- リセットは全状態で利用でき、タイマーとアニメーションを止めて準備状態へ戻す。
- 完了後の「もう一度」は1回目の吸うフェーズから開始する。
- 連打しても更新処理を重複起動しない。

完了条件: 全状態からの操作を検証し、到達不能コードがなく、ボタン表示と動作が一致する。

### R-05 DB初期化と起動手順【必須・優先度高】

- FlywayでPostgreSQLのテーブル作成をバージョン管理する。使用中のSpring Bootに対応する依存関係を実装時に確認する。
- 初期マイグレーションはEntityと一致する `breathing_records` を作成する。ID自動採番、各列のNOT NULL、秒数・回数のCHECK制約を含む。
- JPAはマイグレーション後の整合性を検証する設定とし、自動更新でスキーマを変更しない。
- 既存DBに対して初期DDLを無条件実行しない。バックアップ、スキーマ・既存値の確認、必要な差分適用、ベースライン設定の手順を分ける。
- READMEにJDK 25、PostgreSQL、DB・ユーザー作成、ローカル設定、Windows/POSIXでの起動、テスト、アクセス先を記載する。
- 実接続情報をコミットしない。

完了条件: 空の検証用DBから起動して登録・一覧・タイマーを利用できる。再起動でDDLが再適用されず、既存データが残る。

### R-06 回帰テスト【必須・優先度中】

- Controller: 正常保存、不正入力、入力値保持、保存処理の未呼び出しを検証する。
- タイマー: 0秒、遅延、停止・再開、リセット、完了後再実行、連打、タブ非表示を模擬時計で検証する。
- DB: PostgreSQLの独立したテスト用環境でマイグレーションと永続化を確認する。個人用DBに接続しない。
- テスト実行の前提とコマンドをREADMEに記載する。Testcontainersを採用する場合はDockerを前提に明記する。

完了条件: 手順書の受入テストを満たし、実施結果と未実施事項を記録する。

## 4. 追加改善・公開条件

| ID | 区分 | 要件と完了条件 |
| --- | --- | --- |
| R-07 | 追加 | 登録・一覧にもviewportと日本語langを設定。幅360pxで登録フォームが収まり、一覧は表の領域内で横スクロールできる。タイマーは幅320pxでも円や操作が画面外に切れない。 |
| R-08 | 追加 | 一覧を作成日時降順・ID降順にする。0件時に案内を表示。大量データへのページングは別途判断する。 |
| R-09 | 追加 | 音のオン／オフを設け、状態を表示する。音声再生が拒否されてもタイマーは継続する。初回は音あり、設定の永続保存は必須にしない。 |
| R-10 | 公開前必須 | 全件閲覧・匿名登録を許可する現状を解消する。公開範囲と認証方式を決定し、個人記録として運用するなら全アクセスに認証と所有者単位の制御を実装。CSRF保護を有効化し、トークンなしPOSTが拒否されることを確認する。詳細設計が済むまで外部公開しない。 |
